# Repository scope

- Keep this repository focused on reusable personal configuration and necessary supporting code.
- Keep machine-local state, secrets and work-specific details out of versioned files.
- Prefer the smallest change that meets the request. Do not add speculative abstractions, helpers or files.
- Documentation describes the desired setup and indispensable operating instructions, not session history, migration plans, investigation results or task lists.
- Treat configuration and code as the source of truth. Do not duplicate their values or narrate their implementation in Markdown.
- Use existing documentation instead of adding READMEs by default. Every additional file must have a concrete, lasting purpose.
- Test executable behavior and meaningful safety invariants; do not add tests that merely freeze personal preferences.
- Preserve third-party licenses and concise source attribution without maintaining a prose change history.
